## 1. Cycle Failure Characterization

Two structurally distinct failure modes have been identified. They have different triggers but a
shared root cause: **test infrastructure state is not reset between cycles, and signal routing
thresholds are not calibrated for passing-test timing output**.

### Mode 1 — "Completes then glitches"

The test cycle runs to completion but side-effects accumulate silently and the repo remains in a
persistently dirty state. Manifestations:

- `artifacts/inference_gap_ledger.jsonl` — 4 identical fixture patterns appended on every run that
  touches the agentic/reasoning tests. Each run adds 4 entries with fresh gap_ids but identical
  span text, source, and confidence values. The file is tracked but never committed. The working
  tree shows a modified file after every run with no cleanup step.
- `dev/navigation_graph.json` — modified on HEAD, uncommitted. Likely regenerated by an
  intelligence navigation run that does not clean up its output artifact.
- `DIAGNOSTIC.md` itself — was written as an untracked file and never committed, leaving no audit
  trail after the previous session closed. The diagnostic record exists on disk but is invisible to
  git history.

These three files together cause the working tree to be perpetually dirty after every session
without any CI gate catching it.

### Mode 2 — "Persistent glitch if out of scope"

Signals that originate outside GRID-main's actual failure domain are misclassified as critical by
the ori signal router, inflating the apparent failure count and masking real root causes.
Manifestations:

- `test_execute_skill_timeout` (and `test_fallback_timeout_when_subprocess_blocked`) — both tests
  pass. Their wall-clock timing lines (`2.00s call ...`, `1.00s call ...`) contain the word
  "timeout" and trigger the critical-escalator route on every run. Confirmed: the route fired
  twice during the Apr 10 runs (audit entries `synth-2026-04-10T11:48:34.298Z` and
  `synth-2026-04-10T10:41:43.303Z`).
- The HMAC admission gate failure (now resolved) also exhibited this mode: the gate rejected
  before HMAC evaluation, making 5 tests look like signing infrastructure failures when the
  actual cause was badge provisioning in test fixtures. The failure pattern was indistinguishable
  from a real security regression until the log trace was read carefully.
- 22 `console_error`-tagged log entries from pre-commit scans and mcp-grid-server tests were
  surfaced as warnings against grid-main's health score even though they originate from different
  sources.

**Shared structural cause:** The critical-escalator route triggers on any single critical-severity
log line regardless of whether the source test passed or failed. The "timeout" pattern is broad
enough to match test names containing the word, not just hung processes.
